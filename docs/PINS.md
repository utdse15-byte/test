# Source-scanning pin tests (F23)

A **pin** is a test that reads *raw source text* (or a frozen registry/skill
file) and asserts a token is present, absent, or confined to an owner — a
grep-style guard, not a behavioural test. Because the assertion scans text, a
token in a **comment or docstring** trips it exactly like real code: per
`CLAUDE.md`, "several tests scan RAW SOURCE TEXT, so a token in a COMMENT or
docstring trips them (this has burned four recorded sessions; see DECISIONS #38,
#41 and the ratemig/c21g entries)." When a loop touches a pinned surface, honor
the batch rule — quoting `CLAUDE.md`: "a loop touching surface X re-runs the
UNION of the previous X-loop's verification batch — per-loop batches kept
dropping the pin that then went red on the definitive run."

This index enumerates every pin verified by reading its test. It extends the
top-3 grep-pins already named in `CLAUDE.md`; it never contradicts them.

## Evolving a pin honestly

A pin exists to catch a specific regression that already bit. Evolving one is
legitimate — the ratemig1 pin widened its sanctioned set exactly as R1
anticipated — but only under this discipline:

- **Red-first.** Change the pin's assertion in the same commit that makes the
  change necessary, and watch it go RED before green. A pin that was never seen
  to fail is not proven to have teeth.
- **State the pin's intent.** Keep (or refresh) the docstring so the next
  session knows what the pin protects and WHY — ratemig1's docstring, which
  names each sanctioned consumer, is the model.
- **Never weaken silently.** Widening an allow-list, deleting a needle, or
  excepting a file is a reviewed, explained change — not a quiet edit to get
  green. Per `CLAUDE.md`: don't weaken existing tests.
- **Record the evolution.** Name the change in the commit message (and, for a
  landed wave, add the `DECISIONS.md` entry + `REPORTS/INDEX.md` row). The four
  recorded burns live in DECISIONS #38 / #41 and the ratemig/c21g entries.
- **Re-run the UNION batch.** When a loop touches a pinned surface, re-run the
  union of the previous loop's verification batch, never a trimmed per-loop
  subset (the quoted batch rule).
