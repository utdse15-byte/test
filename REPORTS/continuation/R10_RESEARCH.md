# R10：型号变化要可审查，不让项目跟着网页漂移

核验日：2026-09-06（项目对话日；文件快照另用实际 UTC）。
以下区分官方资料、继承事实与本轮工程决定。没有商业 API 调用，没有画质、速度、费用实测。

## 1. Runway Gen-4.5：新增独立网页作者档
官方来源：https://help.runwayml.com/hc/en-us/articles/46974685288467-Creating-with-Gen-4-5

官方文档列明文本和单图视频生成、2至10秒、720p；表格中的文本路径为16:9，图片路径另支持竖屏、方形和超宽等画幅。24/25fps不属于现有请求协议，本轮不扩张该协议。超宽规格为1584×672；720p标签不能被不加判断地等同于所有画幅短边720。

本轮决定：新增 `runway-gen-4-5-web`，仅覆盖该文档可核验的文本和单首帧模式。`product_workflow` 明确表示这份档依据网页工作流，不表示“这个型号一定没有 API”。不从其他Runway Apps借用视频编辑或尾帧能力，不加入价格表，不自动提交。

## 2. Google Omni：重新核验，不重复创建
官方来源：https://ai.google.dev/gemini-api/docs/omni

官方API文档的精确型号为 `gemini-omni-1.1-flash`。1080p/4k标为上采样；上传视频编辑/延展受10秒输入和地区限制。上传音频参考不受当前接口支持。未从这份文档确认普通生成的可靠整数时长参数，不猜成固定8秒。

源代码核对发现：R7已经有该精确型号的独立档，也已经将它与Veo分开。因此最终R10不再加入重复别名，不改旧档的语义或输入哈希。早期R10工作稿中的重复档已移除，未进入发布提交。已有档连同证据日期原样保留。完整比较记录可用 `models catalog-review` 生成。

## 3. 学习工作方式，不复制模型陈列柜
本地实现决定，不是对竞品实现细节的推断：

- 工作现场应包括实际视频和未完成文字，而不只是任务JSON。R8为显式完整备份；浏览器缓存不是唯一恢复机制。
- 草稿回收后先判断规格差异，再进行人的创作评审。R9不把元数据匹配当作批准，也不把“2K”翻译成假定像素。
- 模型能力变化先呈现字段差异和当前镜头的影响，再显式替换。R10不自动查网页、不追逐排行榜、不代替用户选型号。日期窗口只是目录声明，不是远程验证。
- 新旧档可以复核、预览回退；既有素材和审片历史不改。完整工作现场仍是跨窗口/跨机器恢复的主要形式。

## 4. 主动保留的边界
API有文档不等于已接通；新增档也没有供应商账户可用性证明。
H3/H3-Max、Veo、Omni及旧工作流的八个继承档在本轮保持原值，旧包使用自己封存的能力快照验证。没有把新目录偷偷用于判定历史审批。
多轮远程会话、实际计费与取消、供应商媒体上传、回传下载都没有被这次目录改进冒充完成。下一次真实执行集成应独立解决这些状态，而不是绕过现有审批或强行把新API塞进旧请求对象。
