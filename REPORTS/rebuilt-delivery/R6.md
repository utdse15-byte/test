# R6：实际候选审片与定稿证据

R6 是 R5 的累积版本，不是原版 R3/R4 字节恢复，不是 Windows 正式发布。

## 已实现

离线单文件工作台添加候选审片：实际本地视频、随机化 A/B 标签、显式揭示文件名、一起从头播放/暂停、人工记录、可选评分。没有模型画质自动排名、自动选片或 Picture Lock 写入。播放不是逐帧同步；隐藏文件名不是科学双盲。

审片场次固定草稿请求与候选内容哈希。决定按顺序链接前一决定哈希，修改/拒绝不会抹去先前批准；本记录中最新决定为修改/拒绝时不得晋升。JSON、Markdown 均可独立下载，JSON 不嵌入全部视频，需要保留原文件。导入记录不会自动覆盖上方任务，需要明确载入；重新绑定实际视频后才能记录或晋升。

定稿只允许更改阶段、已批准草稿哈希和分辨率。提示词、时长、画幅、输入素材等变化会阻断旧批准。R6 新建定稿交接必须有实际视频和有效审片记录。v2 包包含 `DRAFT_REVIEW.json` 和 `approved-draft/<SHA>.mp4`，本地验证器同时检查记录链、创作请求与实际媒体字节。

旧 R4/R5 v1 包继续可验证，原黄金夹具未改变。旧 v1 定稿中的哈希只被报告为声明，不冒称有审片证明；`--require-promotion` 拒绝没有实际证明的包。这里的哈希是自洽检查，不是身份签名；老的批准快照也不是联网撤销服务。商业模型仍未连接。

CLI：`manju review create/verify/decide/promote/report`，写出新文件而不覆盖旧记录。`manju models bundle` 新增 `--draft-review` / `--draft-file`；`manju models verify` 新增 `--require-promotion`。

## 实际验证

`r6-core-bounded.xml`：139 通过、1 跳过，覆盖 R3/R4/R5/R6 重建测试与 FFmpeg 取消单元测试。唯一跳过是沙箱不支持的 file:// 重载和 localStorage 场景。不同范围有重叠，不累加。

R6 新增专项 `r6-third.xml`：37 通过。此前保留了测试导入路径错误、测试字符串轮询触发 CSP 拒绝的原始记录，已改为不依赖隐式模块路径的浏览器夹具和函数轮询；没有放宽产品 CSP。

`r6-rehearsal/RESULT.json`：真实生成两个本地测试视频，浏览器实际播放、追加人工测试声明、下载审片 JSON、晋升、实际下载定稿 ZIP，再由 Python 校验器独立核验。两份原视频哈希未变化，页面错误 0、HTTP(S) 请求 0、商业生成调用 0。实际草稿为合成测试片，不是画质测评，也不是用户对真实影片的批准。

浏览器使用真实 Chromium 和原 HTML 字节的 isolated_document 传输。沙箱禁止直接 file:// 导航，因此不是 Windows 双击验收。桌面和 390px 视图截图保存在 `r6-rehearsal/`。

两次扩大到旧 R2 界面等测试的运行触及工具 200 秒截止，被外部终止，未生成完整 JUnit。其原始进度日志 `r6-combined.log`、`r6-core.log` 保留，不能当作全量通过。后续核心范围完整完成。旧界面全回归与 Windows 实机仍未验收。

## 使用

双击包内 `OPEN_MODEL_WORKBENCH.html`，或通过 `manju models workbench --output 工作台.html` 导出。先规划草稿，再添加外部生成后返回的候选视频；审片区所有批准必须由使用者明确填写。晋升后重新选择适配路径、确认并下载 ZIP。请在浏览器下载列表确认保存到自己的磁盘。

浏览器单文件 128 MiB、总量 512 MiB，后端单素材 2 GiB；这些是本地资源上限，不是厂商支持承诺。审片 JSON 2 MiB 上限，过大时另建场次；不会先写出无法再次读取的大文件。
