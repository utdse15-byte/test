# 从用户使用出发：找对恢复点，而不是盲选日期

当前痛点不是再增加模型按钮，而是在多镜头、多窗口续作后难以区分恢复点。已有记录只显示时间、容量和随机窗口号。新入口主动读取已存在的内容，只返回镜头/方案/任务摘录、素材和审片数量、返工与导演内容、未处理意见和模板状态，明确筛选仅覆盖短摘要。

不引入新项目格式或数据库。POINT.json、Desk/v1与Studio/v1保持原字节；服务重启后还能由原版本读取。摘要缓存仅存在本页内存，重新点击会重新检查文件。窗口保存序号负责本窗保留顺序，系统钟只用于列表展示。

额外修复在实际演练中暴露的两类误导：列表开了却看不到按钮、读取过程中又写了新内容却仍显示旧保存成功。显式区域与延迟脏状态通知取代脆弱依赖。

读取是只读核验，不是批准、自动恢复或独立备份。确认恢复仍用旧的强校验和预览；自动续作仍默认关闭。没有迁移旧恢复目录，用户也不必导出导入一遍才升级。本轮不是模型排名研究，原能力目录和质量优先名单保留。

仍需用户本机验收：Windows原生入口、完整影片依赖安装、大容量恢复性能、磁盘/断电场景。摘要没有全文搜索、自动整理或云端索引，不假装能找回已丢失字节。
