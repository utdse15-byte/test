# Manju R16 · 0.2.0+r16.8：故事依据接到实际制作

实际维护版 0.2.0+r16.8，基于已恢复的 r16.7。不是原来丢失的 R17 或长篇管理尝试的复原。

## 直接开始
完整解压到新目录，打开 START_HERE.html，再进入工作台。普通 HTML 无需 Python 或账号。已有工程和旧版本不覆盖。

最快体验：在首页“打开材料”选 `EXAMPLES/STORY/STORY_CHECKOUT.zip`，核验、预览、确认。示例 ZIP 不用解压。在“镜头与素材”中看到三个场景、五份依据、两份制作版本。原版本是“按住箱子”，新版本是“主动交出”；旧简报保留并提示待复核。这里的图视频是合成测试，不是商业 AI 作品，也不是你的真实批准。

从空白开始：镜头与素材 → 建立故事工作本 → 选择作品形态 → 添加人物与依据 → 添加场景。没有工作本时沿用旧工作方式。

## 本轮的四件事

**先选择作品形态。** 单片、限定长篇、可续订系列、竖屏短剧、音乐影像或自定义是创作路线，不是供应商能力。没有固定集数、镜长、付费卡点，也不自动选择模型。

**按实际顺序与明确范围取前情。** 场景从上到下是播放顺序，前移/后移不改变稳定编号。人物、关系压力、设定、事实/伏笔、跨场后果使用稳定资料编号。本场只引用你勾选的资料，不塞整库。

新资料默认仅作者可知。可声明从哪场起公开，或哪位人物从哪场知情。默认制作视角是观众截至本场；人物视角不自动继承其他场景的前情正文。作者视角可能带结局，必须主动选择。范围控制只作用于已标注的结构化来源；本场动作、自由文本和原素材中的剧透需要你自行检查，工具不理解并自动抹除自然语言秘密。

**固定制作版本。** 点击“记录本场制作版本”保存当时的动作、对白、引用、参考职责和场序。上游工作副本改变，旧版本显示需要复核；未引用资料和没有带入的未来场景内容变化，不牵连无关简报。旧版本不就地改写、不会自动重生成。完全恢复原内容后可以重新显示一致；这是内容一致性，不是严格历史无变化证明。

**参考与复盘分开。** 复用已绑定实际文件，逐份写它负责身份、空间、表演、镜头、声音、音乐或外观中的哪一项，及不应继承什么。一份文件能有多项职责。简报ZIP包含冻结文本与本场原参考，内容去重不转码。明确把简报带入镜头才替换镜头编号和提示词，其余素材、时长、画幅不动，旧批准清除。故事改变或手动改了已关联提示词，会阻止带着旧关联继续规划；可明确解除关联，文字保留，但之后不再检查它与原故事的一致性。

实际复盘记录看到了什么、听到了什么、偏差与时间位置，可绑定候选的真实内容哈希。它不会修改原故事，也不是审片批准。相机移动、表演、语义和声音都需要真实回看，不采用帧差阈值作为自动裁判。

## 日常收工只需保存一份；外发按需拆开

- 顶部“保存收工包”：没有故事时仍输出原 Desk/v1；存在工作本时输出 Desk/v2，包含整个故事、旧简报、复盘、三个工作区和原有未处理改稿/模板。点击下载只表示发起下载，选回实际文件核验后才确认与当前工作一致。
- “导出完整故事 JSON”：含作者计划、未完成内容和历史简报，不含任何原媒体。可在外部按协议修改，重新打开时先核验、预览、明确确认替换整个故事副本；不是 R15 外部文字三方合并。不会自动替换当前镜头。
- “下载简报与参考 ZIP”：发给外部工具的当前冻结版本，不是全库或整工程备份。每个角色的职责与哈希见 BRIEF.json，说明见 README.md，实际原文件在 media/。哈希只验证一致，不证明供应商身份、版权或画质。
- 旧“三工作区总备份”与内层 STUDIO.zip 均不含故事，界面会提醒。有新故事的新外层收工包不能假称旧软件支持；旧 r16.7 实测能恢复其内层 STUDIO.zip，原素材与旧工作区不变。

故事依赖里的历史哈希不是原文件。若参考从所有实际工作区移除，故事记录本身不会额外保管那份原片；需要保留此前已外发的简报ZIP或已核验完整收工包。外发时必须重新绑定缺失原文件。临时导入/带入预览与页面视图位置不属于创作备份。

可选本机续作也可以保存 Desk/v2，摘要可按故事标题查找。仍需要已有 Python3.11+，只有主动开启才写入。恢复点不是独立备份，不保护硬盘故障和最后尚未成功写入的输入。

## 主影片与原剧集的只读接入

已有系列管理、共享 Bible 和连续性功能保留。下面命令把共享 Bible 的稳定条目作为作者资料导入工作副本；不猜人物心理、不推断场景、不反写原工程，也不自动同步后来的上游变化。

```text
manju models story-from-series "原剧集目录" --output "故事工作本.json"
manju models story-check "故事工作本.json"
manju models story-brief "故事工作本.json" S10 --output "本场上下文.json"
manju models story-kit-verify "STORY_BRIEF_....zip"
```

新输出拒绝覆盖已有文件。原剧本或 Bible 后来变化，需要重新导入并人工复核，不能把当前工作副本当成对磁盘文件的实时监控。导入的是 Bible 人物/场景/道具/风格/声音条目，不是跨集完整剧本。

总备份仅覆盖此离线页面原有三个工作区，不能把旧式总备份当成包含故事的收工包。保存完整新工作请用顶部收工包。

## 当前范围

单工作本规范化 JSON 最多1MiB，最多512项依据、512场、128份固定简报。每场最多64项引用、32份参考职责，可取最近0–20场前情。大量历史版本需另存分卷，不是无限数据库。原媒体单文件128MiB、去重总量512MiB、高分辨率图和导演锚点原限制均保留。

本轮是可编辑、可外发、可复核的故事制作桥接，不是完整人物关系图、全剧语义审计、自动防剧透、多作者协同或自动长期记忆。模型质量名单不变，没有自动降档、商业生成、上传、付款、选片或锁片。

完整影片应用仍需要 Python、FFmpeg/FFprobe 与项目依赖。Windows实机安装、原生双击、退出、升级回滚和全项目回归未完成认证。实际浏览器证据使用完整原HTML的隔离文档，不能冒充Windows原生验收。

## 下载完整性

完整包和上手包使用同一份页面。配套助手可检查实际大小和SHA-256，也可把本轮五个分段ZIP还原成同一份完整包；分段不要解压、无需排序。先把文件保存到自己的硬盘，再选回助手核验。附件不是永久网盘，主影片工程、外部剪辑工程和原始素材另存第二份备份。
