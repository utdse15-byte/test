# 分集拆解(series-breakdown)

短剧的结构在动笔前就定死了:**在第几集让观众掏钱**先想清楚,再倒推每集的钩子与反转。本技能是把长稿拆成分集的**逐步程序**;拆完的每一集进 `series-bible` 的三层结构,再走 `creation-funnel` 出片。

## 什么时候不该用

这个技能**只**管上面 frontmatter `when_to_use` 说的那件事。误触发比漏触发贵——被拉进相邻场景后,agent 会照着这里的决策树一路走完。以下情形请转走:

| 情形 | 去哪 |
| --- | --- |
| 集数与结构已定,现在做的是其中一集 | `creation-funnel` 走单集流程 |
| 要维护的是跨集人设 / 世界观 / 伏笔 | `series-bible` |
| 片子本来就是单集短片 | `narrative-pacing` 管结构就够 |

## 决策树:先判形态与来源

- **竖屏/小程序** → 1–3 min/集、**80–100 集/部**;首 3 集免费(黄金三集);卡点密。
- **横屏「缩水版」** → 7–10 min/集、通常 ≤30 集;或走精品 **12 集横屏**中间路线。
- **来源是小说/长稿** → 先「取框架」压缩(见下),再拆集。
- **来源是原创长剧本** → 直接三层次拆解。

## 红果 三层次拆解法(权威平台口径,照这个拆)

1. **宏观**:一句话概括全剧(≤100 字 一句话简介)。
2. **中层四阶段弧**(各一个核心任务 + 情绪递进):**前 10 集 / 10–30 集 / 30–60 集 / 60 集–结局**。
3. **微观 每集框架**:**开场 3 秒设钩 → 冲突建立 → 反转设计 → 结尾卡点**。禁水台词。

craft 共识:**每集结尾留悬念,每 3–5 集一个小高潮,每 10 集一个大反转**;单集 = 钩子–发展–反转–收尾,**500–1200 字**。[*这些每集节奏是从业者共识,非单一官方标准。*]

## 卡点 / 付费点(驱动整个结构)

对 80 集:**卡一 ep 8–12(点燃时刻)· 卡二 ep 26–30(再起波澜)· 卡三 ~ep 60(高潮前的高潮)**;首 3 集免费 = **黄金三集**。每集结尾一个**钩子**,3 秒内让人停下、60 秒内勾起好奇。编剧三点论 = **卡点 + 冲突点 + 反转点**,反转要「快、狠、合理」。

## 小说 → 短剧「取框架」压缩(网文改编)

几十万字压到 ~5 万字,三步:**取框架**(保爽点/核心 CP/情感节点)→ **世界观** → **爽点节奏 + 情绪弧线**。别逐字搬,砍支线保主线。

## A/B/C 故事线(西方编剧室做法,可借)

A = 主干、B/C 环绕;**先破每集的幕点(act breaks first)→ beat sheet → outline → 剧本**;编织顺序常「A→C→A→B」。beat-sheet 那层正是市场空白(见 `creation-funnel`)。

## 拆解程序(逐步)

1. 开工三步;若稿在 `story/imports/` 里(`manju import` 会把 `.txt/.md` 改道进去),**通读全文,绝不改动原稿**(只读语义)。
2. 写**宏观一句话** + 四阶段弧(各核心任务/情绪),定卡一/卡二/卡三落在哪几集。
3. 抽人物/场景/道具/核心冲突/结局 → 落进 `series-bible` 的设定层(每角色 `character_id` + 视觉负载)。
4. 逐集写**集纲**:logline、A/B/C 线、3 秒钩、冲突、反转、结尾卡点、免费/付费 + 卡N 标记。
5. 分集脚本**只存状态增量**(换装/受伤/情绪),外观引用 bible(见 `series-bible`)。
6. 单集进 `creation-funnel` 出分镜;备案合规为 advisory(微短剧需备案号,标题禁绝对化,见 `cover-and-title`)。

## BEFORE / AFTER(业余 → 专业)

**例 1 — 平均切集、无付费点设计**
- BEFORE:把长稿按字数平均切 80 段,结尾都是自然段落。
- AFTER:先定卡一 ep8–12 / 卡二 ep26–30 / 卡三 ep60,每集结尾落在钩子上。
- WHY:短剧靠卡点驱动追更;平均切割没有停不下来的钩子,留存崩。

**例 2 — 小说逐字搬**
- BEFORE:把 30 万字小说逐章改成剧本,支线冗长。
- AFTER:取框架(爽点/核心 CP/情感节点)压到 ~5 万字,砍支线。
- WHY:短剧要爽点节奏;逐字搬 = 节奏拖沓、成本爆炸。

**例 3 — 每集结尾松垮**
- BEFORE:集末「今天先到这里」式自然收尾。
- AFTER:每集结尾一个 3 秒钩子/反转,3–5 集一小高潮、10 集一大反转。
- WHY:结尾钩子是追更引擎;松垮收尾直接流失。

## 失败目录

| smell | 抓法 |
| --- | --- |
| 平均切集、无卡点 | 本清单;卡一/卡二/卡三 未落位 |
| 小说逐字搬、节奏拖 | 未做取框架压缩 |
| 每集结尾无钩子 | 与 `narrative-pacing` 交叉;集末 `dialogue` 复查 |
| 改动了原稿 | 硬规矩:`story/imports/` 只读,产物写到 outline/script/bible |
| 跨集人设漂移 | 见 `series-bible` 三层 + `character-consistency` |

## Manju 落地

- **导入原稿**:`manju import novel.txt` → `story/imports/<名>.md`(可改编、只读原稿)。
- **产物**:分集 outline/script/集纲 + `bible/`(角色带 character_id);连续性三件套 `追踪/`(伏笔/时间线/角色状态,见 `series-bible`)。
- **预设**:`manju new --preset` 可作短剧模板起点(竖屏形态)。
- **单集出片**:每集进 `creation-funnel`;拆镜/一致性见 `shot-design`/`character-consistency`。
- **备案/合规**:advisory;Manju 从不发布。

## 验收 eval

1. 给一个 80 集需求,是否产出四阶段弧 + 卡一/卡二/卡三落位 + 黄金三集?
2. 给一部长篇小说,是否先取框架压缩再拆集而非逐字搬?
3. 每集集纲是否含 3 秒钩→冲突→反转→卡点且人设走 bible 引用?
