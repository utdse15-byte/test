# Manju 本机续作维护版 · 0.2.0+r16.2

## 最少的操作
把 ZIP **完整解压到新目录**，打开 `START_HERE.html`。点击“进入创作工作台”即可沿用原离线入口，不需要 Python、账号或安装。要尝试示例，在工作台首页打开 `EXAMPLES/CHECKOUT.zip`，核验、预览、明确确认；示例 ZIP 不用再解压。

下载完整包较慢时，可以用配套下载助手把五个分段 ZIP 合成同一份完整包。分段不需要解压，也不靠文件名排序。保存完整 ZIP 后再选回核验。下载助手只校验本轮记录的固定文件，不联网、不上传。请把包和助手存到你自己的备份位置，聊天附件不承诺永久在线。

## 可选：启用本机续作
已有 **Python 3.11+** 的 Windows 设备，双击 `OPEN_CONTINUE_WINDOWS.cmd`。其他系统运行 `python3 LOCAL_CONTINUE.py`。这是可选入口，没有 Python 仍能直接打开 HTML 并手动保存收工包。续作入口只用 Python 标准库，不安装第三方库；完整影片应用另有依赖。

在新打开的工作台顶部，主动勾选“在本窗口开启自动续作”，或者点击“立即存一份恢复点”。没有这个动作就不创建恢复目录。自动续作在停笔约 8 秒后尝试保存，两次自动保存至少间隔 30 秒；大素材需要更长时间。只在页面仍运行时保存，不指望关窗瞬间完成写入。

控制台没有自动打开浏览器时，复制它显示的本机地址。**保持这个控制台运行**；按 Ctrl+C 会停止续作服务，但不删除已完成的恢复点。重新启动后，通过“查看已有恢复点 → 核验并预览恢复”找回，再明确确认。不会自动覆盖新页面。

默认目录为用户主目录下的 `ManjuRecovery`，Windows 通常是 `%USERPROFILE%\ManjuRecovery`。它独立于解压的软件目录，升级时不用迁移浏览器缓存。启动时可以通过 `--recovery-dir` 明确指定另一目录；不要指向已有影片工程。不支持链接或重解析点目录，不会把不属于 Manju 的目录当作恢复目录写入。

## 保存的范围
与原收工包完全一致：三个工作区的实际媒体和草稿、已载入但未接受的外部改稿、已载入的个人模板和相关未完成文字。原片和高分辨率目标图保持原字节；没有自动转码、缩图或质量降档。

不包含：整部影片工程、外部剪辑软件工程、未绑定的磁盘文件、未应用能力档/组合预览、临时撤回点和播放器位置。缺少必要媒体时不能创建空壳恢复点；请补齐素材，或者先从“外部工具往返”区导出文字。

## 恢复点不是独立备份
本机写入和文件校验成功，只表示那一份现场已经写进当前机器。保存过程中继续输入的文字不会被冒充已经保存。同一硬盘无法防护硬盘故障、机器丢失、恢复目录误删或尚未成功写入的最后输入。

**收工仍应下载收工 ZIP，并在首页选回实际文件核验；另存到第二个安全位置。** 从本机恢复不会清除独立备份提醒，不恢复当前批准勾选，也不自动接受外部意见、付款、生成或选片。

## 多窗口、容量与失败
每次打开工作台使用独立窗口身份。每个窗口只有在新恢复点成功发布后才清理自己的旧点，保留最近 3 份；不会清理其他窗口。默认恢复目录上限 2 GiB、最多 64 份；单个收工包上限 520 MiB，对应原来媒体总量 512 MiB 和有限元数据，不放宽 128 MiB 单素材限制。

保存前要有足够空间容纳新点，**不会先删旧点腾空间**。达到上限、网络中断、写入失败或校验不符，页面会说明未完成，自动续作暂停或等待重新尝试。已完成旧点保留。可先“另存收工 ZIP”，再明确删除不需要的恢复点；删除自己的最新点会暂停本窗口自动续作，避免删后立即写回。

中途关闭进程可能留下未发布的临时写入。列表会报告它们，只有明确选择“清理中断的临时写入”才清除，已完成点不受影响。损坏目录不会被当作正常恢复点自动覆盖；请保留原目录检查。

## 文件能否带回旧版
每个已完成恢复点目录里的 `DESK.zip`，以及页面“另存收工 ZIP”产生的文件，都是既有 Desk/v1 收工包。它可以交给原 R16 工作台核验和恢复，不锁定在本机服务中。不要把整个 `ManjuRecovery` 目录当作工作台 ZIP 导入。

## 需要完整影片应用
仅上手小包不包含源码历史和影片安装包。完整包中先读 `APP/QUICKSTART_ZH.md`，按需运行 `APP/INSTALL_WINDOWS.cmd`，成功后再用 `APP/START_WINDOWS.cmd`。该应用需要 Python、FFmpeg/FFprobe 和项目依赖；续作入口本身不替代完整影片工程的备份。

## 范围说明
只绑定本机 127.0.0.1 随机端口，随机路径和请求令牌，每次启动更新；核对 Host/Origin，禁止跨站请求、任意文件访问和目录浏览。不作为公网或局域网多人服务使用。恢复文件不加密、不带发布者签名；同一操作系统账户和管理员可能读取文件。

本维护版从已验证的 R16.1 继续开发，不冒充此前丢失的 R17。Windows 实机安装、原生双击和跨平台持久化矩阵仍待验收。测试沙箱阻止原生 file/localhost 导航，隔离 Chromium 文档与真实 HTTP 服务的组合演练不等于原生端到端验收。
