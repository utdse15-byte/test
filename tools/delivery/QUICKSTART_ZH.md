# Manju R13：个人创作台，一份总备份保留三个工作区

R13 是累计修复候选版，继承 R3 至 R12。原版 R3/R4 ZIP 未找回，相关功能为重建，并非字节级复原。Windows 正式发布门没有标绿。

## 先使用免安装工具

完整解压 ZIP 到新的文件夹，双击 `OPEN_MODEL_WORKBENCH.html`，使用现代 Edge/Chrome 等本地浏览器。不要在 ZIP 预览窗口内运行，不覆盖旧版本或真实影片工程。

页面不需要 Python、账号、服务器或生成额度。首页可直达准备镜头、审片与定稿、局部返工、导演材料。默认质量优先，没有兼容方案就停下，不自动使用便宜或弱一些的型号。旧档仅作主动打开的历史兼容视图。

质量名单和十二个型号档沿用 R12，保留核验/复核日期与精确内容身份；本轮没有重新做画质排名。作者档是规划和交接约束，不是已经接通的商业生成 API。实际生成仍在你自己选择的外部工具里进行。

## 收工前，只需保存一份三工作区总备份

点击首页“保存三个工作区 · 总备份 ZIP”。它保存镜头任务与审片现场、返工草稿、导演材料，包括已绑定的真实图片/视频、已应用能力档、审片历史、还没提交的审片意见，以及尚未写完的原始文字。

返工时间先后还没改好、导演镜头名还没填写、某个时刻的目标图还没做完，也可以先保存，不要求为了备份把半成品冒充已完成。返回像素、待定稿分辨率和下次添加素材的用途也会保留。三个区引用同一文件时只存一份内容，原片和高像素目标图不会被压缩转码或缩小。

**总备份仅覆盖此离线页面的三个工作区，不是完整影片工程备份。** 外部编辑软件工程、未绑定的文件、原影片项目目录仍需要独立备份。没有实际绑定的引用文件会阻止生成空壳备份。

下载按钮只表示交给浏览器发起保存，不证明已经落盘。到浏览器下载列表确认文件，再点击“核验已下载文件”，选回刚保存的 ZIP。只有文件校验通过且内容与当前三个区一致，页面才标记已核验；这个操作不会替换当前工作。继续编辑会重新提示存在未备份修改。只导出任务 JSON 不会消除总备份提醒。

浏览器可能不触发关闭提醒，文件丢失或设备故障也不在页面控制范围内。请把 ZIP 复制到你自己的备份位置；这不是自动保存或后台同步。

## 在新窗口恢复

点击“核验并预览恢复”，选中总备份 ZIP。先校验所有引用文件、哈希、ZIP 结构与实际媒体，再显示将替换的工作区、视频/锚点数量与恢复边界。此时当前工作不动。

先另存当前工作，再勾选确认并应用。恢复是替换三个工作区，不是合并。预览后继续修改任何工作区，旧预览会失效；正在读取另一份文件时也不会覆盖。可以随时取消预览，保留当前工作。

恢复后视频直接可播放，无需重绑原文件；历史审片记录仍在，但当前型号选择、确认勾选与批准动作全部清除，质量优先重新开启。旧审片记录不是你对新任务的新批准。恢复不生成、不上传、不付款、不剪接，也不修改原影片工程。

未应用能力档预览、派生规格报告和播放器播放位置不保存。规格检查可以由真实文件重新计算；总备份不是新的模型交接执行单。

## 原来的单区 ZIP 仍然可用

原“镜头任务与审片现场 ZIP”、第06区返工 ZIP、第07区导演 ZIP 的格式、核验和入口保持不变。发送局部返工要求或导演材料给外部工具时，继续使用相应交接包。

旧镜头现场 ZIP 不包含返工/导演区；旧单区包也不会自动补成三工作区总备份。载入需要的旧包后，使用首页的新总备份另存即可。总备份文件名以 `MANJU_STUDIO_` 开头。

第06区交接完整原片、毫秒范围和保留/改变要求，不自动裁剪或重绘。第07区保存运动底片、SDR 原尺寸参考帧、同画幅目标 PNG 和关键时刻要求；目标 PNG 可以比原片像素更高，原样保留。它们均不保证外部模型一定保持范围外画面或动作。

SDR 参考帧不是 HDR/EXR 母版，播放器毫秒不是认证帧编号。单文件128 MiB、共享媒体总512 MiB，导演最多16个锚点；目标 PNG 还受单图32 MiB、单边8192、总像素33,554,432限制。这些是本地工具限制，不是供应商能力。

## 命令行的只读核验

```text
manju models studio-verify MANJU_STUDIO_example.zip
manju models workspace-verify WORKSPACE.zip
manju models repair-verify REPAIR.zip
manju models director-verify DIRECTOR.zip
```

Studio CLI 只读验证文件闭包、字节校验和有界 PNG 结构，不提取或执行文件，不完整解码 PNG，也不重新探测视频。浏览器恢复另外完整解码所绑定 PNG，并复测实际视频的时长/尺寸。技术核验不意味着创作质量合格。

已有的完整视频帧解码检查仍可使用：

```text
manju models inspect-return request.json --candidate returned.mp4 --decode --output new-report.json
```

## 完整影片应用

影片应用管理本地工程、镜头候选、人工选片、时间线与出片；离线工具管理外部模型的规划、材料与审片证据。原影片界面“模型”导航可打开离线工具，镜头任务导出只读，不会把审片记录写成自动选片或锁片。

完整应用需要 Python 3.11 或更高、FFmpeg/FFprobe 等依赖；本包不附带这些程序，不自动下载浏览器、模型或权重。双击 `INSTALL_WINDOWS.cmd`，明确输入 `INSTALL` 才在本目录创建独立 `.venv`；通常需联网安装依赖，不修改全局 Python、不覆盖旧 `.venv`。

安装成功后双击 `START_WINDOWS.cmd`，启动先核对包与版本，只监听本机，默认 `strict_zero_cost`。本地占位预演不是顶尖模型生成。使用新目录安装，真实影片工程放在交付目录之外，首次用副本试运行。保留旧安装作为回退，不原地覆盖。

已有离线依赖 wheels 时，在完整包目录运行：

```text
python LAUNCH.py install --wheelhouse "另一个目录里的兼容依赖 wheels"
```

不要向封存的 `wheels/` 添加未知文件，否则完整性校验会拒绝。

## 下载包校验与诊断

```text
python VERIFY_PACKAGE.py
python VERIFY_PACKAGE.py --git
python LAUNCH.py diagnostics --save
python ZIP_CHECK.py "MANJU_R13_CUMULATIVE.zip" --sha256 "收据中的64位SHA256"
```

`--git` 在临时目录恢复历史、验证阶段继承并重放 R2 补丁。`ZIP_CHECK.py` 可追加 `--extract-to "尚不存在的新目录"` 安全解压。诊断只记录工具/版本事实，不导出账号令牌、环境变量或个人路径。

SHA-256 与独立保存的收据用于确定文件一致性，不是发布者数字签名；Git/source/wheel 一致也不等于 Windows 实机通过。单区和总备份的内部校验同样不能证明作者身份、版权或恶意替换前的真实性。
