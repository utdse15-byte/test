# Manju R11：先保存完整工作现场与返工原片

R11 是完整累计修复候选版，包含 R3 至 R10 的改进。原版 R3/R4 ZIP 没有找回，本包不是它们的字节级恢复，也不是 Windows 正式绿灯。

## 最快入口：不安装 Python

完整解压下载的 ZIP 到一个新的、路径尽量短的文件夹。不要在 ZIP 预览窗口里直接运行文件，不要覆盖旧版或真实影片工程。

双击 `OPEN_MODEL_WORKBENCH.html`，用现代本地浏览器打开。它是一个离线文件，不需要 Python、账号、服务器或模型额度。浏览器若只显示源码，请选择“打开方式”为 Edge、Chrome 等浏览器。

填写镜头、绑定素材、检查适配、明确确认后保存任务 JSON 或素材 ZIP。模型档是创作约束和交接说明，不是已接通的生成服务。

得到外部工具生成的视频后，在审片区添加候选，实际观看，填写人工决定。保存完整审片 JSON 和原视频。只有批准过的实际草稿才能晋升；晋升后重新检查适配、导出定稿 ZIP。这个包会包含批准草稿的视频字节和审片记录。

每次导出，请到浏览器“下载”列表确认保存，再把文件放入你自己的项目备份位置。页面不能观察你是否在系统保存窗口中点了取消。浏览器草稿不是永久备份。


## R8至R10新增的日常使用方式

**离开前保存完整现场。** 点击“保存完整工作现场 ZIP”，同时保存任务文字、能力档、审片历史和实际媒体。JSON导出依然可用，但不替代包含媒体的ZIP。新页面使用“恢复完整工作现场 ZIP”，逐项验证后再确认替换；当前确认勾选会清除，旧审批记录仍在。

**返回视频先检查，再审片。** 展开审片区的“返回视频是否符合任务规格？”，读取实际文件后核对时长、像素画幅和本地最低短边。未知规格不会装作通过，匹配也不意味着内容好或已批准。CLI的 `manju models inspect-return request.json --candidate video.mp4 --decode --output new-report.json` 可额外完整解码视频帧；仍不评价声音或创作质量。

**更新能力档先看差异。** 导入新的目录后先展示字段变化、当前镜头的选项变化和复核日期。勾选并应用后才替换；工作现场改过必须重新预览。可预览恢复上一目录。通过目录更新不授权生成、付款、选片或锁片。

R10新增Gen-4.5网页作者档；已有Omni、Veo、H3/H3-Max和其他工作流保持独立。不要求你迁移原工程，也不接通商业账号。

## R11：只交接需要修改的范围，不丢原片

展开第06区“只返工出问题的片段”，选择实际视频，填写开始/结束秒数（最多三位小数），写清保留项、改变项和声音要求。可用播放器当前位置标记范围；上下文预览仅辅助观看，不是逐帧精确剪辑。

明确确认后导出“返工 ZIP”。其中包含完整原片、返工单、说明和清单。原视频不裁剪、不覆盖、不上传；不会自动调用模型、拼接或选片。模型是否接受这种局部修改仍需外部平台确认，不能据此保证画面保持不变或节省费用。

新窗口可重新打开这份 ZIP，先验文件再确认替换返工区，原片不必重新选择；上方任务和审片历史不被修改，当前确认会清除。**返工区是独立工作区，不包含在旧版“完整工作现场 ZIP”内，请单独保存返工 ZIP。** 原任务仅作上下文，其中引用的其他素材不会自动打进返工包。

返回规格检查新增“明确像素尺寸”。例如 Gen-4.5 的 21:9 标称720p实际是1584×672，不能用统一短边720判断。参考按钮需要明确点击，宽高可手工修改；这不识别供应商来源，也不批准画质。未填写宽高时，原有v1检查行为不变。像素检查临时选项不会随工作现场备份。

新增 Seedance 2.5 的 BytePlus LAS 作者档，精确型号为 `dreamina-seedance-2-5-260628`。这条具体入口按官方480p/720p、4至30秒约束规划；其他平台的1080p宣传不可移植为本入口能力。不是新增可直接执行的商业API。

```text
manju models repair-create request.json original.mp4 --start-ms 1000 --end-ms 2500 --preserve "服装与构图" --change "修正手指" --requested-by "作者" --human-confirmed --output new-repair.zip
manju models repair-verify new-repair.zip
manju models inspect-return request.json --candidate returned.mp4 --pixel-width 1584 --pixel-height 672 --decode --output new-report.json
```

返工ZIP校验验证字节和声明一致性，不独立重新探测视频元数据，不证明作者身份、版权或范围外画面保持不变。完成外部修改后仍须人工检查接缝、全片、声音与创作要求。

## 已安装完整影片应用的入口

原工作台导航已有“模型”，会在新标签打开离线模型和审片工具。当前工程的镜头任务可以直接下载，再导入工具，不必使用命令行。这个导出接口只读，不修改工程，不自动选片。

模型工具和影片工作台仍然分工：模型工具做约束、交接与审片证据，影片工作台管理本地项目、候选、选片与出片。没有把审片批准偷换成影片 Picture Lock。

## 安装完整影片应用

需要 Python 3.11 或更高版本。媒体制作还需要符合项目要求的 FFmpeg/FFprobe 等工具；本包不附带它们，也不自动下载浏览器或生成模型。

Windows 下双击 `INSTALL_WINDOWS.cmd`。它会明确询问是否在本目录创建独立 `.venv`，首次依赖安装通常需要联网从 PyPI 获取 Python 依赖。只有输入 `INSTALL` 才执行；不修改全局 Python，不覆盖旧 `.venv`，不调用付费模型。

安装成功后双击 `START_WINDOWS.cmd`。启动会先验证包与版本，以 `strict_zero_cost` 模式仅监听本机地址。需要安全停止时使用应用退出功能；前台命令窗口中的 Ctrl+C 也会停止服务。

已有旧安装请保留，R11 在新目录中安装。真实工程放在交付目录之外，首次用副本验证。升级回滚靠保留旧目录，而不是原地覆盖文件。

离线依赖已经准备好的使用者，可以在本包目录运行：

```text
python LAUNCH.py install --wheelhouse "另一个目录里的兼容依赖 wheels"
```

默认不联网。不要往已经封存的 `wheels/` 里塞入额外文件，否则完整性验证会拒绝未知文件。

## 核验与诊断

双击 `VERIFY_WINDOWS.cmd`，或运行：

```text
python VERIFY_PACKAGE.py
python VERIFY_PACKAGE.py --git
python LAUNCH.py diagnostics --save
```

`--git` 需要已安装 Git，会在临时目录克隆完整历史、验证各阶段祖先关系并重放 R2 补丁，不修改交付目录中的源码。诊断仅保存程序版本、依赖工具是否可见等事实，不导出环境变量、账号令牌或个人路径，结果在 `local-logs/`。

下载 ZIP 在解压之前也可以检查：

```text
python ZIP_CHECK.py "MANJU_R11_CUMULATIVE.zip" --sha256 "收据里的64位SHA256"
```

需要安全解压时追加 `--extract-to "尚不存在的新目录"`。工具会检查 CRC、危险路径、重复条目、Windows 大小写/Unicode 冲突和体积上限，不执行归档里的代码，不覆盖已有文件夹。

SHA-256 与外部保存的收据一起用于确定文件一致性；它不是发布者数字签名。Git/source/wheel 一致也不等于 Windows 实机通过。

## 发生问题时

若链接没有得到 ZIP 文件，先检查浏览器下载列表。单文件离线工具 ZIP 体积更小，也包含完整模型规划与候选审片页面；它不替代完整项目包，但可独立使用。

若安装缺少依赖，保留错误信息，不要在旧环境上不断叠加安装。若 `.venv` 已存在，安装器会停止，请使用另一份新解压目录。若模型包校验失败，不要手动改 manifest 来“变绿”，保留原包与错误，再重新导出一份新修订。
